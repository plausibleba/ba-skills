D-118 UX Prototype v3 — Design Notes

1. Generated vs Provided External Inputs

Inputs now have a provenance badge: Provided (user uploaded) or Generated (AI-created from model content). Three input types can be generated: Risk Register (from friction analysis), Metrics Library (from industry + VS type benchmarks), and Maturity Assessment (from PPIT depth analysis). Generated inputs have a "Regenerate" action in their detail view. Provided inputs have higher confidence weighting.

The ✦ Generate button appears alongside "+ Add" on input types where generation is available. Operation cards show Gen badges alongside external input references so the user always knows whether a diagnostic is working from user-supplied or inferred context.

2. NBA Across Visualisations

A floating banner component (NBABanner) renders in the top-right of any canvas view. It reads from the NBA engine and shows contextually relevant actions:

• On the Capability Map: "Derive Activity Flows" — the next enrichment step
• On the Value Stream Canvas: "Friction Analysis is outdated" — when a stale diagnostic's overlay is visible
• On the Friction Heatmap: "Heatmap from scaffold v3, now on v5" — with a Re-run button and desaturated overlay

The banner is dismissible (× button). It slides in with a subtle animation. It's compact enough not to obstruct the canvas but present enough that the user always knows what the tool recommends next. The "Go" button navigates to the enrichment page with the relevant operation pre-highlighted.

3. External Input Detail View (View All)

Clicking any provided/generated chip or the "View All" button opens a modal/drawer with full content:

• SWOT: 2×2 grid with Strengths/Weaknesses/Opportunities/Threats, each item with confidence and severity badges
• Risk Register: table with risk ID, description, likelihood, impact, mitigation, capability references
• Metrics Library: table with metric name, target, baseline, quartile benchmarks, scope (VS/stage/capability)

Each detail view shows a "Consumers" section — which operations use this input — and footer actions: Edit (provided), Regenerate (generated), Replace (swap generated with a provided version). Click a SWOT chip below to see the detail view demo.

4. Provenance Architecture

ExternalInputArtefact gains a provenance field: "provided" | "generated". Generated inputs also track generatedFrom (the operation or model state that produced them) and generatedAt (scaffold hash at generation time, for staleness). The NBA engine gives a +5 bonus for operations with external inputs present, but applies a -2 penalty for generated inputs vs provided ones — nudging the user toward providing real data when available.

5. Interaction Summary

Enrichment page:
• Click external input chip → opens detail view with full content
• "+ Add" → upload provided input
• "✦ Generate" → AI creates baseline from model
• "View All External Inputs →" → opens detail modal scoped to all inputs

Canvas views:
• NBA banner auto-appears when next action is available
• Stale diagnostic overlays are desaturated (opacity 0.4, saturate 0.3)
• Banner shows stale-specific messaging when on a view with stale overlays
• "Go" / "Re-run" in banner navigates to enrichment page or triggers re-run directly
