# /opmodel-context

Produce a Context Document for an organisation and the division or function in scope, before any
discovery or workshop. Every line says where it came from and how sure we are.

> **Tip:** Run this first, send the document to the customer for correction, then run
> `/plausibleba` (or the three skills separately) on the corrected sections 4–6.

## What this command does

Loads ba-taxonomy-standard and ba-opmodel-context, then:

1. **Gather** — reads every source once for the register before reading any for content
2. **Frame** — settles the scope to a division or function, in one sentence
3. **Anchor** — picks the industry standard that already names the disciplines, stages and objects
4. **Extract** — fills fourteen sections, one marked and sourced claim per line
5. **Question and score** — the known unknowns paired with the documents that would settle them; readiness against the Discovery weights
6. **Checkpoint** — pauses on scope and the source register before rendering

## Output

- `CONTEXT-<org>-<date>.md` — the document, for the customer and the room
- `discovery-transcript.md` — the same material in the voice the PlausibleBA Discovery door reads

## Works best when

- You have a folder of the organisation's public documents (annual report, governance
  statement, investor materials) and the regulator's and industry body's material for the function
- The customer will correct the document before a model is built from it
- You want to show a prospect exactly what public input produces before asking for their documents
